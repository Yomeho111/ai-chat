# ai-chat-web 

## 回答来源标识

每条机器人回答的时间戳后显示醒目的来源标签，用户消息不显示：

- **绿色「向量数据库命中」**：本次请求直接使用向量数据库检索命中的答案。
- **蓝色「大模型 API 返回」**：本次请求由大模型接口生成答案，即使该答案随后写入向量数据库，仍显示此来源。
- **黄色「系统敏感词拦截」**：系统拦截提示，不属于向量库答案或模型生成内容。
- 等待响应时显示「来源识别中」；旧记录、旧版服务或未提供来源的响应显示「来源未知」，不推测来源。

来源字段随聊天记录一起保存在本地，刷新页面后保留；重新生成回答时会清除旧来源，并按新响应更新。标签支持深色模式、移动端换行和现有的中英文切换。

来源由 `ai-chat-service` 的实际处理分支写入流式和非流式响应的 `source` 字段（`vector_db`、`llm_api`、`sensitive_filter`），由 `ai-chat-backend` 透传到 `/chat-process` 的每个 JSON 数据块。发布本功能时需同步更新服务端、后端及前端；两个 Go 模块内的聊天协议和生成代码保持一致。

## Token 消耗与节省统计

页面右上角展示 **Token 统计**，每条机器人回答下方以小字展示该回答的消耗量和节省量。总数按当前浏览器本地保存的所有会话中的机器人回答计算，不包含用户消息的重复计数：

- **大模型 API 回答**：消耗量为现有 tokenizer 的请求输入计数（包含实际发送的系统提示、上下文及既有消息封装开销）与完整回答计数之和，节省量为 0。该结果沿用项目 tokenizer 的估算口径，不等同于供应商账单。
- **向量数据库命中**：消耗量为 0，节省量为本次问题和命中答案分别经 tokenizer 计算后的 Token 数之和，不包含未发送给模型的系统提示或上下文。
- **敏感词拦截提示**：消耗量和节省量均为 0。

后端通过 `tokenUsage` 返回 `consumedTokens` 和 `savedTokens`。流式响应只在终止数据块附带完整计数，前端使用快照替换而非逐块累加；自动续答会合并各次请求的消耗与节省量，且等待上一请求完成后再继续。

统计随回答一起持久化，刷新后保留；删除回答、清空会话或删除会话时同步扣除，重新生成时只统计新回答。旧记录、旧版服务、尚未结束或中断的响应没有完整统计时显示明确提示，不伪装成 0；已知的续答部分计入总数，同时提示仍有未完整统计的回答。统计不追溯已删除的记录，也不包含其他浏览器或用户的用量。

tokenizer 失败会通过现有错误通道返回，不会伪造计数或将向量库命中改记为 API 消耗。此功能需同步更新聊天服务、后端协议与前端。

## node 安装
### windows
1. 上[官网](https://nodejs.org/en)下载18.16.0 LTS版本
2. 查看node 是否安装成功
```
node -v
npm -v
```
3. 安装pnpm
```
npm install pnpm  -g
```

### ubuntu
1. 设置 apt 源，设置后可查看/etc/apt/sources.list.d/nodesource.list 文件
```
curl -sL https://deb.nodesource.com/setup_18.x | sudo -E bash -
```
2. 安装nodejs
```
sudo apt-get install -y nodejs
```
3. 验证
```
node -v
npm -v
```
4. 安装pnpm
```
sudo npm install pnpm -g
```

## 编译运行
1. 依赖安装
``` 
pnpm bootstrap
```
2. 本地运行
```
pnpm dev
```
3. 打包发布版本
```
pnpm build-only
```
